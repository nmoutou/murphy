F13 Pas de type-checker — les type: ignore ne signifient rien pyproject.toml · hooks.py:369 · telemetry/factory.py:56 à corriger

F14 truncations : course entre workers, comptage par moitié, absent du run failed adapters/embedding/openai_embedder.py:262 · hooks.py corrigé

L'embedder est partagé entre workers : self.truncations += 1 est une lecture-modification-écriture non atomique entre threads (incréments perdables). Il compte les moitiés successives, pas les chunks (un chunk raccourci trois fois compte 3). Et _declare_truncations n'est appelé que dans after_pipeline_run — jamais dans on_pipeline_error.

compteur par chunk (au point d'entrée de la dichotomie), protégé ou par-boucle puis sommé ; déclarer aussi dans le chemin d'erreur.

F15 Sémantique de compteur incohérente : upserted par batch, pending par arête application/resolve_relations.py:97-110 · telemetry/aggregator.py:_weight_of corrigé

RELATION_PENDING est émis et compté par arête ; RELATION_UPSERTED une fois par batch, le vrai compte dans payload["count"] — repêché par _weight_of uniquement parce que la clé s'appelle count. Le contrat est implicite et fragile : un payload renommé casserait le bilan sans un test rouge. Graver le contrat dans telemetry_events.py (quel event est unitaire, lequel est porteur de cardinalité) — ou unifier.

F16 La compensation d'un UPDATE détruit l'ancienne version application/ingest_document.py + adapters/storage/mongo/document_repository.py corrigé

Le forward Mongo faisait delete puis insert — une fenêtre à vide créée par notre propre code, que le rollback rendait durable. Corrigé : l'upsert Mongo est désormais un replace_one(..., upsert=True) atomique ; la branche if UPDATE: delete et le helper _mongo_delete_then_insert ont disparu. Plus aucun instant à vide côté document.

Deux faits ont recadré la portée : (1) nuke_all efface le manifest → après un nuke, tout est INSERT et le chemin UPDATE est inatteignable ; le trou ne concerne donc que le run incrémental, un chemin v1. (2) Qdrant garde son delete-then-insert — nécessaire (un document = N points ; un UPDATE plus court laisserait des points orphelins qu'un simple upsert n'enlève pas) et documenté comme tel pour qu'on ne le « corrige » pas par erreur. Le résiduel saga-multi-store retombe sur l'at-least-once ; le vrai rollback versionné est un choix explicite de v1, écrit dans la docstring de la saga.

Ce qui est remarquablement bon — à ne pas « nettoyer »

La revue vaut aussi comme inventaire de ce qui doit survivre à tout refactoring.

  • La scission WorkflowConfig / InfraSettings — garantie par le type, pas par discipline — et le golden test_fingerprint.py qui la verrouille.
  • Le vocabulaire ouvert des verbes (core/links) : l'arête inconnue existe sous son nom brut, et l'aveu remonte au bilan.
  • UnknownRef et describes_targets — la découverte qui fait exister le graphe juri.
  • L'équation de complétude, testée dans le bon ordre (la fiabilité des compteurs d'abord).
  • AsyncRuntime.spawn/drain — le runtime qui retient ses tâches, et le port qui sépare drain() de close().
  • Le monoïde RunStats, la partition par clé, une boucle par worker : le verrou supprimé par construction.
  • Tables de rôles, registre de sources, catalogue d'events : la donnée déclarative contre le branchement conditionnel, partout.
  • Les messages d'erreur qui contiennent leur propre remède, les noqa tous justifiés.

La porte de fin de v0

v0 = préparation et ingestion naïves, évaluées automatiquement sur leur qualité technique. La porte est close quand chaque critère ci-dessous est vert — dans cet ordre, chaque chantier rendant le suivant vérifiable. On ne coche jamais sur parole : le critère se lit dans une commande ou dans une base.

G0Le gate mécanique

Un script unique (scripts/gate.sh ou cible npm) qui enchaîne : ruff check + ruff format --check → pytest → pytest -m integration → kedro run nuké (6 sources) → assertion programmatique status == ok lue dans MURPHY_META.meta_run_summaries — jamais dans les logs. Variante --smoke (une petite source) pour l'itération. C'est le squelette que le benchmark v1 étendra avec des métriques métier.

une commande, verte de bout en bout, exécutée avant chaque commit. Résout F12 au passage.

status == ok en base · fetched == persisted + invalidated + failed avec failed == 0 · meta_published_collection pointe l'empreinte du run.

Le backend (submodule backend/) lit le pointeur meta_published_collection au boot au lieu de QDRANT_COLLECTION=chunks. Côté ingestion tout est prêt ; c'est le seul point qui bloque le produit, et il vit dans l'autre dépôt.

une question posée au chat rend une réponse sourcée depuis la collection publiée par G5.
Hors porte, explicitement. Le Lot C (embedding maison + chunker en tokens), la résolution juri (registre d'alias + extracteur de références), le benchmark de pertinence (jeu de questions de référence) et le breakdown par source du bilan (§12) sont des chantiers v1. Les inscrire ici diluerait la porte ; les oublier serait pire — ils sont nommés, datés, et attendront que la porte soit close.
